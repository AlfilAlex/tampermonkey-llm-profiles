# Design

## Decision

`activeState.body` is the single canonical note document.

`activeState.cornell` remains in draft state only as a structured projection used to render Cornell and Repaso efficiently.

```text
                ┌───────────────┐
Libre editor <--│ canonical body │--> filesystem Markdown
                └───────┬───────┘
                        │ parse / serialize
                ┌───────▼───────┐
                │ Cornell blocks │
                └───────┬───────┘
                        │
                     Repaso
```

There is no longer a separate "Libre document" and "Cornell document".

## Canonical Cornell Markdown

The body representation is intentionally ordinary Markdown:

```markdown
## Cornell Notes

### 1. What is longest-prefix match?

The kernel chooses the most specific matching route.

### 2. Nota

A block with no cue still preserves its notes.

## Summary

Routing selects a route before resolving the next hop.
```

### Structural grammar

A body is considered structurally Cornell when:

1. it contains a line exactly equal to `## Cornell Notes`;
2. a later line is exactly `## Summary`;
3. block boundaries between them are headings matching:
   `### <integer>. <text>`.

The parser only reserves that exact numbered level-3 heading form inside the Cornell section. Other Markdown headings inside a block remain note content unless they match the reserved numbered-block syntax.

A heading whose normalized label is exactly `Nota` maps to an empty cue.

Completely empty blocks are omitted during serialization.

## Synchronization

### Cornell -> Libre

Every content-changing Cornell operation calls `syncBodyFromCornell()`:

- cue edit;
- notes edit;
- summary edit;
- add block;
- move block;
- delete block.

That function serializes the current Cornell structure into `activeState.body`.

Switching to Libre therefore only renders the already-updated canonical body.

### Libre -> Cornell

Libre edits update `activeState.body` while the user types and invalidate the cached Cornell projection. Because `body` is authoritative, the stale projection must not survive as if it were an independent document.

When switching to Cornell or Repaso:

1. attempt to parse `activeState.body` as canonical Cornell Markdown;
2. if parsing succeeds, replace the Cornell projection with the parsed blocks and summary;
3. if parsing fails and the body is non-empty, import the complete body as one Cornell block with an empty cue;
4. serialize that result back to canonical Cornell Markdown so future mode switches are deterministic.

No text is discarded.

## Existing Draft Migration

Normalization uses these rules.

### Existing body already parses as Cornell

The parsed body wins because it is the new canonical representation. The Cornell projection is rebuilt from it.

### Body empty, Cornell has content

Serialize the legacy Cornell state into body.

### Body non-empty, Cornell empty

Keep body as-is. It stays a normal freeform note until the user enters Cornell.

### Body non-empty and legacy Cornell also has content

If body does not already parse as Cornell, preserve both:

1. create a first Cornell block with empty cue and notes equal to the previous freeform body;
2. append every legacy Cornell block in its existing order;
3. keep the legacy Cornell summary;
4. serialize the merged structure into body.

This migration is intentionally preservation-first even if it changes the visual representation of a draft that previously contained two divergent note bodies.

## Dirty State

Because body is canonical, dirty state becomes:

```text
body != savedBody
OR resolved filename != last written filename
```

Changing only the view selector does not make the note dirty.

Legacy `savedCornellSnapshot` and `savedNoteMode` are ignored for dirty-state decisions.

## Save Semantics

`buildMarkdown()` always writes `activeState.body` after frontmatter and title.

If the body parses as Cornell, frontmatter includes:

```yaml
note_method: "cornell"
```

Otherwise that field is omitted.

Saving from Libre, Cornell, or Repaso therefore produces the same document bytes for the same body.

After a successful write:

```js
activeState.savedBody = activeState.body
```

## Repaso

Repaso never owns content.

Before Repaso renders, the Cornell projection is synchronized from the canonical body using the same Libre -> Cornell rules.

Reveal/navigation state remains ephemeral and does not alter body.

## Limits

The first implementation does not provide a full general-purpose Markdown AST parser.

The structured parser is intentionally scoped to the Markdown shape generated by this userscript. A user can always edit arbitrary Markdown in Libre; if the Cornell structural markers are no longer parseable, entering Cornell preserves all text by importing the whole body into a single block rather than guessing and potentially losing content.
